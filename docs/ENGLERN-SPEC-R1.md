# ENGLERN-SPEC-R1 — English Learning & Pronunciation Studio

Статус: PROPOSED, требуется согласование. Реализация не подтверждена данным документом.

## 1. Назначение
Локальное настольное приложение для самостоятельного изучения английского A1–C2, произношения, аудирования, словаря и профессиональной коммуникации. Цикл: Study → Listen → Repeat → Speak → Compare → Remember → Improve. Windows x64 и macOS Apple Silicon; Intel Mac — отдельная квалификация.

## 2. Архитектура
Модульный монолит Python 3.12 / PySide6. Presentation → Application → Domain; инфраструктурные адаптеры Piper TTS, Qt Multimedia, SQLite, ASR, IPA/G2P. Тяжёлые операции вне UI thread, отмена и обработка ошибок. Версии и лицензии зависимостей проверяются на R1. Без сервера, обязательной регистрации и облачной передачи записей. Офлайн после загрузки моделей.
Предлагаемые модули: platform, audio, learning, pronunciation, vocabulary, professional, adaptive, persistence, ui. Названия и миграция существующего кода согласуются после R0.
Сущности: Lesson, LessonRevision, Sentence, VoiceProfile, AudioArtifact, TrainingSession, Recording, RecognitionResult, VocabularyEntry, ReviewEvent, LearningPlan. Стабильные ID, версия схемы SQLite, транзакционное сохранение прогресса. Аудио в локальных файлах, относительные ссылки в БД. Удаление записи удаляет связанный файл либо регистрирует повторную очистку.

## 3. R0 — Source Baseline (P0)
R0.1 Инвентаризация исходного ZIP, контрольные суммы, происхождение и лицензии.
R0.2 Импорт исходников без моделей, venv, cache, build, dist, секретов. .gitignore; инструкция восстановления моделей. Не распространять модели без подтверждения лицензии.
R0.3 Сохранение исходной версии и описание отличий адаптированной версии. Проверка синтаксиса, исходного запуска и перечня известных дефектов.
Gate: исходники доступны из чистого clone, все исключения документированы, воспроизводимый запуск или явно зарегистрированный blocker; тег baseline после проверки. README не считается полным импортом.

## 4. R1 — Cross-Platform Foundation (P0)
R1.1 Фиксируем зависимости и платформенные адаптеры. QStandardPaths для данных, cache и настроек; ресурсы приложения отдельно от пользовательских файлов.
R1.2 Voice Manager: manifest (voice ID, locale, version, URL, SHA-256, license, config); модель ONNX и JSON как единый комплект; загрузка во временную область, проверка целостности, атомарная публикация, отмена, retry, удаление. Не считать частичный комплект готовым.
R1.3 Audio Service: синтез в worker, очередь, отмена, ошибки, WAV, cache с ключом текста/голоса/версии/параметров. Не блокировать UI.
R1.4 CI: Windows x64 и macOS arm64, проверка фактической архитектуры runner, unit/integration/packaging smoke. Нативные сборки PyInstaller; исходные инструкции.
Gate: clean install, startup, загрузка голоса, синтез, проигрывание и повторный запуск на обеих ОС; offline smoke после загрузки; реальные GUI/audio проверки отдельно от headless CI.

## 5. R2 — Learning & Audio Engine (P0)
R2.1 Библиотека A1–C2: уровень CEFR как редакционная классификация, тема, язык, ревизия, текст, предложения, словарь, вопросы, источник/лицензия. Импорт TXT/JSON, ручное редактирование и проверка сегментации.
R2.2 Режимы Text, Sentence, Listen & Repeat, Shadowing. Навигация, выделение предложения, seek, pause/resume/stop, repeat 1–10 или бесконечно, настраиваемая пауза 0–10 с, скорость 0.5–1.5x (проектные пределы), выбор доступного акцента en-US/en-GB. Если pitch preservation недоступен — явное ограничение.
R2.3 Сохранение позиции, параметров и завершённых упражнений. Импорт собственного текста, генерация и экспорт WAV. Синтез целого текста и отдельных предложений не обязан иметь одинаковый ритм.
Gate: полный сценарий урока, отсутствие гонок при переключении/отмене, восстановление позиции, тесты сегментации (сокращения, числа, пунктуация), корректная работа при отсутствующем голосе. По три оригинальных или лицензированных урока на уровень как начальный каталог.

## 6. R3 — Pronunciation Lab (P1)
R3.1 Выбор микрофона, разрешения ОС, запись/стоп, PCM WAV, индикатор уровня, воспроизведение. Обработка тишины, clipping, отключения устройства и отказа в разрешении.
R3.2 A/B сравнение эталона и записи, повторная попытка, история попыток. Удаление и экспорт только по действию пользователя.
R3.3 ASR адаптер Whisper/faster-whisper после платформенной квалификации; транскрипция, сопоставление слов, пропуски/вставки/замены, WER с версией нормализации. Ошибки распознавания не являются доказательством дефекта произношения. Фонемная оценка — отдельная экспериментальная задача с размеченным набором и проверкой валидности; без неё не выдавать процент правильности произношения.
Gate: запись и A/B на обеих ОС, офлайн ASR после загрузки, тесты ошибок и приватности, корректные примеры WER и невозможность оценивания пустого эталона.

## 7. R4 — Vocabulary Engine (P1)
R4.1 Выделение слова из текста, лемма, часть речи, контекст, IPA по акценту, перевод ru, пример и источник. Различать словарную IPA и прогноз G2P; неоднозначные слова требуют выбора значения/чтения. Не выдумывать перевод при отсутствии словаря.
R4.2 Локальный словарь пользователя: CRUD, поиск, теги, избранное, импорт/экспорт CSV/JSON, дедупликация по лемме/значению/языку. Прослушивание слова и примера.
R4.3 Карточки и повторение (recognition, recall, listening); оценка Again/Hard/Good/Easy, next_due и история. Начальный детерминированный алгоритм, версионирование параметров.
Gate: round trip, корректная Unicode/IPA, воспроизводимый расчёт дат повторения, сохранение прогресса при редактировании, отсутствие обязательного внешнего API.

## 8. R5 — Professional English (P1)
Тематические наборы IT English, HR Interview, Technical Interview, Business English. Сценарии: self-introduction, опыт работы, STAR, Java/Spring/SQL, system design, incident discussion, daily standup, meetings, negotiation.
Вопрос → подготовка → запись ответа → транскрипция → самостоятельная сверка по рубрике (ясность, структура, полнота, лексика). Пример ответа не единственно правильный. Профессиональные материалы B1–C1 с расширением по необходимости. Не заявлять автоматическую оценку технических знаний без отдельной валидации.
Gate: минимум пять сценариев каждого направления, история попыток, собственные вопросы, экспорт ответа и работоспособность без сети.

## 9. R6 — Adaptive Learning (P2)
R6.1 Профиль: самооценка уровня, цель, доступные минуты, тематические предпочтения.
R6.2 Детерминированный план на день: просроченные карточки, упражнения на слабые навыки, новые уроки в пределах бюджета времени; пользователь может менять план. Не путать оценку активности с сертифицированным уровнем CEFR.
R6.3 Метрики: активное время (без пауз), завершённые упражнения, уникальные изученные слова, recall rate с denominator, число записей, WER по сопоставимым заданиям. При отсутствии данных — N/A, не ноль. Графики 7/30/90 дней. Хранить версии алгоритма, исключить двойной учёт.
Gate: тесты нулевых данных, смены часового пояса, повторных событий, воспроизводимости плана, изменения целей и восстановления из backup.

## 10. R7 — Release Qualification (P0 для релиза)
Нативная Windows x64 поставка EXE/installer и macOS arm64 APP/DMG. Версионирование SemVer, release notes, SHA-256, список зависимостей/лицензий, инструкции offline/online. Подпись Windows и Apple signing/notarization при наличии сертификатов; неподписанная сборка маркируется и не выдаётся за подписанную.
Проверки: чистая установка, обновление с сохранением данных, удаление приложения, миграция/backup/restore, сценарии с отказами, права микрофона, доступность клавиатурой, HiDPI. CI артефакты привязаны к commit SHA. Релиз запрещён при открытых критических дефектах или отсутствии платформенной квалификации. Intel Mac отдельно.

## 11. Нефункциональные требования
NFR-01 UI не блокируется синтезом, загрузкой и ASR.
NFR-02 Все длительные операции имеют статус/ошибку/отмену где технически возможно.
NFR-03 Записи и учебный прогресс локальны; никакой телеметрии по умолчанию.
NFR-04 Понятные русские и английские интерфейсы; текст урока сохраняется в исходном языке.
NFR-05 Предварительные цели на согласованном эталонном устройстве: warm startup ≤5 с без загрузки моделей, p95 реакции UI ≤200 мс, отсутствие потери прогресса после штатного перезапуска. Скорость TTS/ASR измеряется отдельно по моделям и устройствам; пороги уточняются R1.
NFR-06 Версионированный backup SQLite + пользовательских файлов; тест восстановления; миграции с проверкой целостности.
NFR-07 Не хранить секреты в репозитории, проверять пути импортируемых файлов, ограничивать размеры и проверять хеши моделей.

## 12. UI и тестирование
Разделы Home/Today, Library, Text & Audio, Pronunciation, Vocabulary, Professional, Progress, Settings. Общий плеер и единые компоненты состояния загрузки/ошибки/пустых данных. Клавиатурная навигация, масштабирование, светлая/тёмная темы.
Unit: доменная логика; integration: SQLite, TTS, аудио, ASR; GUI: pytest-qt; native smoke: реальные устройства/права; E2E: урок → запись → словарь → повторение → прогресс.
Definition of Done: требования, код, тесты, документация, CI на точном SHA, evidence и ограничения. Статусы PROPOSED/IMPLEMENTED/QUALIFIED/HOLD. Нельзя объявлять QUALIFIED только по headless тестам.

## 13. Последовательность
R0 → R1 → R2 → R3 → R4 → R5 → R6 → R7. R7 packaging smoke начинается с R1; финальный gate после завершения согласованного объёма. MVP: R0–R2 + запись/A-B из R3. Дальнейшие функции не должны задерживать пригодную к использованию первую версию.
Следующий приоритет: R0.1–R0.3. Исходники, реальные native builds и качество ASR настоящим ТЗ не подтверждаются. Предложенные количественные критерии и выбор библиотек требуют согласования.
